## 1. 会話の候補と未読表示を一致させた
- 原因：メニュー「はなす」→ 相手を選ぶ経路（追加側の `openTalkMenu`→`speak`→`choose`）が、追加会話（`pt_`・`gm_`）だけから選んでいた。元の会話（第1段の L。追加会話を足す前に入っていたもの）は、未読数には数えられるが、選ばれなかった。
- 修正：
  - 元の会話の ID を、追加会話を足す前に記録（`ORIG_IDS`）。ID・進行条件（`when`）・既読記録（`G.talkSeen`）はそのまま使う。
  - 候補の条件：話す人（`w`）が選んだ仲間か、同席（`need`）にその仲間がいる。そのうえで **`w` と `need` の全員**が隊列にいて、`when` を満たすもの。
  - 優先度（`pri`）がある元の会話を先に。それ以外は追加会話の未読とまぜる。
  - 未読数は、メニューの表示（「はなす」の小見出し・相手ごとの「新しい 話 n」）と、実際に話す候補を**同じ関数**（`unreadOf`・`unreadTotal`）で数える。
  - 話題がない仲間は元の短い反応（人）・鳴き声（モンスター）に戻す（以前は何も起きなかった）。
  - Gemini の修正案は貼っていない（上の方針で書き直し）。
- 検査：未読119件とメニュー表示119件が一致。60回話して、元の会話（`all_first_talk`・`mio_continent_town`・`riku_after_sana` など7件）が選ばれ、既読に記録された。読み終わった相手とも話せる。

## 2. 連携の更新を「状態が変わったときだけ」に
- 状態の鍵：隊列の順、個体（人は id、モンスターは uid）、種族（進化で変わる）、生死、睡眠、MP が各連携の必要量に届くか、なつき50以上か。HP は生死だけを見る（連携の条件が生死だけのため）。
- 鍵が同じあいだは配列を作り直さない。連携がないときは元の配列をそのまま使う。
- 戦闘終了（`battleEnd`）とロードで元の配列に戻し、次の戦闘では必ず作り直す。戦闘外のフレームで古い候補が残らないようにした。
- 検査：60フレームで配列は1回だけ作成。睡眠にすると作り直され、連携が外れた。戦闘終了後は元の配列に戻った。
- **iPhone の処理落ちは未実測**。

## 3. 住人が一時的な障害物で消えたままにならない
- 原因：体がブロックにふさがれると `mobVisible=false` にして、地方を移るまで戻らなかった（描画も会話も）。
- 修正：ふさがれている間だけ隠す（`mobHidden`）。障害物がなくなれば描画と会話が戻る。4秒ふさがれたままなら近くの空いた場所へ移す。置き場所が見つからなかった住人も5秒ごとに置き直しを試す。
- 検査：ブロックを置くと隠れて会話不可 → 取り除くと表示・会話が戻る。置いたままにすると7m離れた場所へ移って表示された。
