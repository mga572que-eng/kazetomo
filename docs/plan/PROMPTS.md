# AIに渡す依頼文：作品として磨く

2026-10-02。正本はROADMAP.md。確認済み公開基準はmain f36a44bbdd9a4ba89bef77e9916492996441e535、版20261002164000。
実際の作業基準は着手時に再確認する。この文書のSHAを無期限に「最新」と呼ばない。

## 使い方

最初はCodexへ「共通依頼」と「C0」を送る。Claudeは同じ基準の設計レビュー、Geminiは1件ずつコードや文の点検をする。
AI StudioがGitHubを自動で読めるとは仮定しない。統括役が基準SHA・必要資料・依頼文を1つにまとめて渡す。ユーザーに資料探しを繰り返させない。
現在の依頼だけで、別サービスへの送信や全段階の実装開始が済んだとは扱わない。

## 共通依頼（毎回最初に送る）

```text
「ともしびアイランド」を、寄せ集めに見えない、統一感のある作品に磨いてください。
リポジトリ：https://github.com/mga572que-eng/kazetomo
最新方針の正本：ROADMAP.md。直近の作業：docs/plan/NEXT.md。
中心は「仲間と旅をして、灯台に明かりを戻す」です。

この依頼に添付されたソースのコミットSHAを最初に明記してください。
Gitを読めるならstatus・履歴・fetchで最新mainと未完了作業を確認。未保存の変更は保全してください。
Gitを読めないなら添付資料だけを根拠にし、ないファイルや過去チャットを確認済みとしないでください。
新しい雛形で置き換えず、既存コードを必要な範囲だけ直してください。
セーブキー・ID・フラグ・HOOK・ロード順を維持してください。無関係な改行統一や全体リファクタを混ぜないでください。
横画面専用。難しい漢字はひらがなにし、固有名詞とコードIDは維持してください。
レベル全回復、騎乗中消費ゼロ、4作戦、牧場同種3体上限、移動中回復を確認なく戻さないでください。
ユーザーが取り消したiPhone確認・PC代替の全章通しテストは再開も予定化もしないでください。
コードから分かること、画面で確認したこと、端末未確認を分けてください。
新しい過去・家族・年齢・事件は既成事実として追加しないでください。
各AIの主張を事実として信じず、同じ基準SHAのソースと照合してください。
不足資料は「必要なファイルと、その何を確認したいか」を一度にまとめ、独立した調査は続けてください。
実装者は1人。確認なく別AIと同じファイルを同時編集しないでください。
最後に変更したこと、実行した検査と結果、未確認、保存先、公開状態を短く書いてください。
実際にGit保存できなければ「未保存」、ローカルだけなら「ローカル保存済み・GitHub未送信」と明記してください。
```

## C0：Codexへの最初の依頼（基準区間を決め、最初の改善を具体化）

```text
まずP0から始めてください。全地域への大改修はまだ行いません。
1. コードで、最初の町・最初に進行可能な灯台・間の道・関係NPC・進行フラグを特定してください。
2. 基準区間の問題を最大5件に絞ってください。根拠のある不具合と見た目の推測は区別してください。

4. 最初のPRの対象ファイル、直す目的、変更しない範囲、完成条件を決めてください。
5. 好みを聞かないと決まらない大きな絵の変更は、比較できる案を用意してください。一般的な視認性修正はそのまま進めて構いません。
成果をdocs/design/quality-baseline.mdに保存。項目は「基準SHA／実区間とID／問題5件／画面基準／最初のPR／未確認」。
新しい部署や機能を大量に足さないでください。証拠なしの点数付け、端末確認の完了宣言は不要です。
```

## C1：Codexへの実装依頼（P1〜P5を1つずつ）

統括役が実行前に「今回のP番号／1つの問題／対象区間／対象SHA」を具体的に埋める。未記入のまま送らない。
資料：共通文書＋quality-baseline.md＋変更対象と参照先のソース。UIならindex.htmlと後からCSSを入れるモジュールも必要。

```text
今回の指定された1つの改善を実装してください。
最初に現在の挙動と原因を確認し、変更の前後を短く説明してください。
役割が重なるメニューや表示は、入口や共通部品を整理してください。同じUIの別版を追加しないでください。
スマホ横画面の文字・操作対象・HP/MP・行動者・目的地を優先してください。
常時点滅、強い全画面フラッシュ、不要な待ち時間を増やさないでください。
同じ部品のスタイルと画面のレイアウトを切り分け、CSSの上書きを積み続ける前に既存ルールを確認してください。
npm run check、npm run test、git diff --checkと今回の動作確認を実行。収支変更ならeconomyも実行。
画面比較できる環境があれば同じ場面・サイズで前後を比較。できなければ未確認と書き、画像を確認済みとして作り話をしないでください。
確認済みの変更だけcheckpoint・バックアップに保存。必要な版番号を同期してください。
公開はセッション内の既存承認に従い、未解決の重大不具合や送信拒否を隠さないでください。
最後は「改善点／検査／未確認／保存・公開／次の1件」。次の段階の大改修を自動で開始しないでください。
```

## L1：Claudeへの設計レビュー

資料：ROADMAP.md、quality-baseline.md、同じSHAの対象ソース、取得できた前後画像。画像がなければ美術評価は暫定。

```text
今回は実装者とは別の設計レビュアーです。ゲームを触った、別部署に確認したと、実際に行っていないことを言わないでください。
基準区間について「見た目の統一／操作の手軽さ／道の意味／戦闘の理解／仲間への愛着」でレビューしてください。
指摘は最大5件、優先順に。各件は「見える問題／資料の根拠／プレイヤーへの影響／最小の改善／確認方法」。
同じ感想を言い換えて数を増やさないでください。根拠のない新しい過去や機能追加で埋めないでください。
最後に採用すべき3件と、後回しにすべき提案を選んでください。
コードやGit保存は今回は行わず、提案として返してください。
```

## G1：Geminiへのコード点検（1PRずつ）

添付必須：対象SHA、AGENTS.md、AI_HANDOFF.md、WORK_STATE.md、GEMINI.md、ROADMAP.md、今回の差分全文と変更前後の必要ソース。
戦闘・回復：game.js、data.js、balance.js、jobs.js、monplus.js、battle3d.js、index.html。
町・移動：game.js、world.js、mobs.js、towns.js、town.js、interiors.js、fieldtravel.js、adventurelife.js、ux.js、対象灯台の実装。
PWA：index.html、pwa.js、sw.js、version.json。今回に無関係な全部のソースは渡さない。

```text
GitHubを自動で読めない前提です。添付の対象SHAと差分だけを今回の基準にしてください。
セーブ互換、既存ID/フラグ、HOOKの競合、ロード順、キャンセル時の消費、HP0/MP不足/隊列不在、毎フレームの負荷、PWAキャッシュを必要な範囲で点検してください。
冒頭に「高重大度の件数」。各指摘は「重大度／ファイル:行／ソース根拠／再現条件／期待と実際／最小修正案」。
ソースだけでは分からない見た目・実機の遅さは、確認済み不具合と分けて仮説にしてください。
修正案を新しい全体雛形として返さないでください。指定外ファイルを書き換えないでください。
行番号は添付基準のものにし、古いレビューを現在の不具合として再利用しないでください。
最後に「未保存・実機未検証」。問題が見つからなくても完全な安全や互換性を保証しないでください。
```

## 制限が来た時の引き継ぎ

```text
前のAIの続きを、同じ作業ブランチと未完了差分から引き継いでください。
まずWORK_STATE.md、AI_HANDOFF.md、ROADMAP.md、git status、最新コミットと差分を確認してください。
前のAIの完了宣言だけで判断せず、コードと検査結果を照合してください。
今回終わらせる目的は1つ。資料が足りない場合は、そのファイルと確認目的だけをまとめて請求してください。
すでに公開した変更を二重に適用しないでください。GitHubを読めない環境では、渡されたSHA/差分を使い未保存の提案として返してください。
```
