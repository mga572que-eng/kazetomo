# ともしびアイランド — AI共通作業ルール

最初に `npm run resume`、`AGENTS.md`、`AI_HANDOFF.md`、存在すれば `WORK_STATE.md` を読む。コード・Git履歴・実際の差分を正とする。ユーザーにブランチ名や引き継ぎの整理を毎回求めず、自分で作業状態を確認する。

- Claude / Codex / Geminiの実装担当は固定しない。交代時は同じ作業ブランチを引き継ぐ。レビューは大きな変更、セーブ互換性、難しい不具合で利用する。
- 作業前に `git status`、`git log -5`、`git fetch origin`。他の担当の未保存変更は保全し、上書きしない。共有フォルダーでは1担当だけ作業する。
- mainは公開版。新しい作業は最新mainから `work/<短い内容>` を作る。交代では新しいmainからやり直さず、未完了ブランチと未コミット差分を確認する。
- 小さな機能がまとまる時、別機能へ移る前、会話終了前、AI交代前にcheckpointを作る。制限到達後まで記録を先延ばしにしない。毎メッセージの保存は不要。
- `npm run checkpoint -- --goal "目的" --done "できた部分と途中の部分" --next "次の具体的な操作" --files <確認した個別ファイル>` は指定ファイルとWORK_STATE.mdだけをコミットする。秘密情報やセーブは内容も目視確認する。既存のステージ済み変更を勝手に混ぜない。
- checkpointはローカル保存。差分と残る変更を確認し、許可された方法で作業ブランチをpushしてGitHubのコミットを確認して初めて他PCから再開できる。送信が拒否された時は迂回せず、保存場所と未送信を明示する。
- 検査が失敗した途中のコードも作業ブランチへWIP保存できる。公開はしない。全変更が保存されたクリーンな状態で `npm run backup` を行う。
- チャットだけにある提案・コードは実装済み扱いにしない。未保存ファイルが取得できなければその点だけユーザーへ伝える。別AIが履歴を自動で読めると仮定しない。
- 既存スクリプト読込順、window.KZ、HOOK、セーブキー、データID、進行フラグを維持。ゲーム変更の公開時はindex/pwa/sw/versionの版番号を同期する。
- localStorage.clear、本番セーブ削除、force push、reset --hard、clean -fdを行わない。実セーブ、秘密情報、チャット全文をGitへ含めない。
- 統合前は `npm run check`、`git diff --check`、変更に応じた実プレイ。必要なレビューを行い、ユーザーの確認後にPRをmainへ統合。保存と公開を区別する。

===== OPERATIONS.md =====

# 普段の運用とAI交代

## あなたが行うこと
使えるAIへ「〇〇を作って」、止まったら別のAIへ「kazetomoの続きをやって」と伝える。最後にプレビューを遊び、公開してよいか判断する。ブランチ管理・検査・保存記録はAIが担当する。
GitHub連携やプロジェクトの選択は各サービスで必要。全AIの自動接続・自動切替はこの設定では行わない。チャット内だけの未保存コードは別途渡す必要がある。

## AIが行うこと
1. `npm run resume`とGitの状態を確認。WORK_STATE.mdの内容を差分と照合する。
2. 新しい依頼ならクリーンな最新mainでbackup後、work/内容ブランチ。交代なら途中のブランチを引き継ぐ。未保存コードは消さない。
3. 目的を1つに絞って実装。小さな単位で下記checkpointを使う。
4. 差分を確認して作業ブランチへpush。リモートのコミットを確認。クリーンな時にbackup。
5. 完成時に検査・実プレイ、必要なら別AIでレビュー。ユーザー確認後にPR統合。

## 途中保存
```sh
npm run checkpoint -- --goal "戦闘UIを改善" --done "表示は実装。タッチ操作は未確認" --next "スマホ操作を確認する" --files ux.js
```
ファイル名は実際に確認した個別ファイルに置き換える。複数ファイルは空白区切り。スペース入りのパスは引用符で囲む。--filesは最後のオプション。
指定ファイルとWORK_STATE.mdを同じWIPコミットへ保存。main/master、切り離されたHEAD、競合、既存のステージ済み変更では停止する。検査失敗はFAILと記録し、途中保存は可能。失敗したコードをmainへ統合しない。
個別ファイルだけを保存するので未選択の変更は残る。秘密情報の除外は名前による補助であり、保存前の内容確認を省略しない。
このコマンドはpushしない。AIはgit showとgit statusを確認し、許可された方法で `git push -u origin HEAD`。GitHubへの保存が拒否された場合は迂回せず、ローカル保存と未送信を報告する。

## Claudeが制限に達したら
次のAIへ「kazetomoの続きをやって。GitHubの未完了ブランチとWORK_STATE.mdを確認して」と伝える。
同じPC・同じフォルダーなら未コミット変更も確認して引き継ぐ。別PCならGitHubへpush済みの変更だけ取得できる。未pushの作業がある時は元PCで保全し、保存を完了してから移る。
制限はコードの削除ではない。途中ブランチをmainで上書きしない。元のAIが復帰しても、最新Gitと作業記録を読んでから再開する。

## 別PC・クラウド
軽い編集はgithub.dev、実行確認はCodespaces。CodespacesのTerminalでnpm run resume、npm run dev、Portsの4173を開く。ローカルとクラウドの保存先は同じGitHub。Codespaces初回起動は別途確認が必要。
保存完了はcommit+push。エディターのSaveだけでは別PCへ共有されない。セーブデータはブラウザー単位で、コードと一緒には同期されない。

## バックアップ
クリーンな状態でnpm run backup。GitHubではActionsのDownloadable Git backupを手動実行。履歴bundle・ソースZIP・SHA256を作る。成果物の保存は30日なので長期保管はダウンロードして別媒体へ保存。GitHubバックアップ実行は確認済み。
